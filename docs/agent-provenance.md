# 参与者身份、步骤与交接记录约束

> **2026-10-23 状态说明：** 当前规划、子智能体派发/审核/合并与 Chat Work 适用边界以[主流程](agent-workflow.md)为准，人工唤醒 Chat 不再是每步必经环节。身份/步骤/隐私要求继续适用；既有每四小时巡检已暂停，本次不恢复自动研究或新增触发器。直接委派也必须保留同样的 GitHub 交接记录。

本约束覆盖 Dot 直接委派的原生子智能体、Codex、Chat Work、通过 ACP 调用的外部 Agent、人工操作，以及它们使用的 RDC 等工具。不要求依赖某个客户端自动记住历史。研究与推演另遵守[实验约束](experiment-protocol.md)。

## 区分执行者、入口、模型和工具

| 字段 | 记录内容 |
| --- | --- |
| `actor_id`、`role` | 执行者的稳定别名和本次职责；不使用凭据或账户隐私作标识 |
| `run_id`、`parent_run_id` | 本次独立运行ID及委派来源；同一模型的两次运行是不同运行 |
| `client`、`transport`、`tools` | 承载客户端、接入方式和实际使用的工具；例如 Chat / 手动或ACP / RDC |
| `model` | 请求的模型、运行方实际报告的模型，以及各信息来源和可核程度 |
| `reasoning` | 请求的思考强度、运行方报告的设置、来源和可核程度；保留原始枚举，不擅自等同不同平台等级 |
| `task_ref`、`owned_paths` | 已授权任务及本次文件归属；记录本身不授予新权限 |
| `read_rules_ref` | 本次读取的约束版本和文件，供后续交接核对 |

RDC属于操作工具，ACP属于接入协议，不能用它们推断背后的模型。委派者与真正执行子任务的Agent分开建运行记录，最终提交者也不自动成为内容作者。新建运行、切换模型/强度或转交执行者时登记新 `run_id`，以父运行关联；不把多个配置覆盖为同一条身份。

采用[运行模板](../templates/agent-run.json)。`model` 和 `reasoning` 各自记录 `requested`、`reported`、`source`、`verification`：

- `runtime_reported`：运行元数据/API返回报告了该值；不是对后端实际模型身份的独立认证。
- `ui_reported`：界面显示该选项；只证明界面显示，不能证明提供商内部路由。
- `self_reported`：执行Agent自己声称，协调者尚未取得独立依据。
- `unknown`：未暴露或无法取得，值填 `null` 并写原因。
- `not_applicable`：例如纯人工步骤；值填 `null` 并说明。

只有启动配置时可填写 `requested`，`reported` 仍为空；不得拿全局默认配置、模型口头自称或前一轮设置冒充本轮运行证据。请求值与报告值不同须保留两者并说明。元数据未知不必禁止一般研究；任务若明确要求特定模型/强度或独立审核身份，未核清该条件前不能视为已满足。旧记录缺失的信息保留未知，不能凭印象补齐。

## 每一步怎样记

一个步骤是一项有意义的工作，例如收集证据、提出规则、运行回合、修改文件、独立审核、整合或提交；不要求记录每次点击、按键或内部思维过程。

采用[步骤模板](../templates/work-step.json)。每条有唯一 `step_id`，记录 `run_id`、任务、前序步骤、输入版本、操作概述、产物路径与版本/哈希、结果、未知和真实记录时间。涉及实验时再引用实验ID、分支和回合。过程只保存简明理由、来源和可核结果，不索取或保存隐藏思维链。

`phase: completed` 只表示该操作执行完毕；是否核实产物另记 `verification`，状态为 `not_checked`、`verified`、`failed` 或 `unknown`，附核验者与依据。后续核验另追加步骤，不回写先前记录，也不把自检冒充独立审核。计划可记为 `planned`，不能据计划预填已发生结果。

改变文件、外部系统或可见状态前，先追加 `phase: started` 的记录；完成后另追加 `completed`、`failed`、`interrupted` 或 `uncertain` 记录，以同一个 `action_id` 关联，并把起始记录列为父步骤。读取和分析可在完成后一次记账。已经登记的记录不覆盖，纠错另添步骤并引用原记录。

`uncertain` 表示操作结果不明，不能自动当失败重试。先读取实际文件/外部状态再决定，避免重复提交。重试使用新 `action_id`，通过 `retry_of` 引用前次步骤；中断后保留已有产物及状态，新运行明确从哪里接续。多个运行各写自己的文件，不并发追加同一个共享日志；协调者负责关联和确认写入归属。

产物引用使用完整提交+仓库相对路径、内容SHA-256，或可以核对的外部对象ID与版本。模型身份记录不包含自己的成果提交，避免自引用；冻结成果后，由后续交接步骤记录该提交。审核仍采用“冻结成果H，再仅追加审核记录R”的既有机制。

## Chat/RDC 和外部Agent的交接

1. 协调者先给出具体任务、授权边界、规则版本、输入位置、运行ID及独占输出位置。RDC可以访问电脑不代表获准读取整个磁盘或操作其他任务。
2. 参与者在第一次写入前返回实际可见的模型/强度信息及来源，登记运行。不能读取仓库的入口，由协调者提供必要规则并记录交付版本；记录遵守声明，不声称客户端自动加载过文件。
3. 参与者按步骤登记结果。若入口无法写文件，返回模板所需的结构化内容，由协调者代录；保留真正执行者并增加 `recorded_by_run_id`，不把代录者当执行者。缺关键结果或版本时先保留待核状态，不代填成功。
4. 交接附输出位置、固定版本、工作步骤记录、未完成事项及写入归属交还。协调者读取实际产物核对；聊天中“已完成”不等于产物已验证。
5. 独立审核者使用自己的运行记录，声明未参与编写并绑定被审版本。不同模型名称、账号或运行ID本身不能证明独立，协调者核实际分工与原始回复。

## 存放、隐私与门禁

每个项目可在 `work/runs/`、`work/steps/` 放置审阅后的结构化工作记录；通用任务可指定独立记录根目录。尚未获准上传的记录放在被忽略的 `local/` 中。准备Issue之前使用稳定的 `LOCAL-...` 任务ID；建立Issue后另追加映射记录，旧记录不改写，不形成两套任务状态。

工作记录是有选择的产物归属摘要，不能夹带完整会话、屏幕内容、机器绝对路径、账号、密钥或原始运行日志。仅在已获准批次中提交最少必要字段；私有来源可用本地不透明证据ID关联，原始元数据留本地。记录是可审计声明，不是密码学防伪身份系统。

交接前必须核对：实际执行者及元数据状态、输入输出版本、未结操作、文件归属和任务范围。关键步骤无归属、缺产物版本或审核独立性不明时退回补录/补证。模型设置未知可按前述规则明示，不编造。

当前没有RDC/ACP自动采集适配器；由执行者或协调者按模板落盘、独立审核核对。不能声称此规则文件会自动拦截所有客户端写入，也不能把现有CI通过当作元数据验证。2026-10-19已取消周期自动唤醒；本规则不恢复定时任务，后续工作仅在获授权的实际运行中执行。

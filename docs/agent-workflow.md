# 学习型研究：规划—调度—执行—独立审核—合并

本文件是当前协作流程的唯一主入口（2026-10-23）。最终目标是支持中国未来十年的学业、职业选择，并落到当前高考志愿与培养路径选择；方法和协作试验是实现该目标的手段，不是终点。项目仍在学习型研究阶段，先完成多个思维实验、比较收益和失效处，再逐步固定整体框架。必要记录服务于理解、复盘和交接，不以 PR 数量、字段数量或自动化规模代替研究进展。

本次仅更新流程与方法文档，不启动新研究单元、工具复测或后台研究。既有有界任务按其实际授权与停止条件处理；写好规则、审核通过或合并均不自动授权下一项研究。当天的目标和职责调整见[决策记录](decisions/2026-10-23-research-goal-and-delegation.md)。

## 规划目标与推演入口

Dot 为每个有界单元明确：它服务哪个十年学业/职业问题、为什么现在做、方向性判断应落到哪里、什么结果可以结束本轮，以及下一步条件。不得把局部案例核查或机械审核循环变成总目标。研究方法按[思维实验方法](research-methods.md)执行：先把前提、逻辑连接和判断写清，只在会改变方向、强弱或选择的关键节点求证；支持与反证均可产生有效收益。

不要求每条逻辑连接先有独立实证才允许继续推演。尚未核实的连接作为明示假设或推断传递，不冒充事实；存在有力反例、关键前提失效或决策相关分歧时才补证、修订或收窄。不能用仅仅“可能存在”的抵消机制把有依据的基准方向冲淡。

## Search 主线与可选 Research

需要收集事实时，主线是：**Search 找线索 → 保存并核对原文 → 另开 Astra 加工 → 独立 Astra 审核 → Luna 按门禁合并**。这是事实收集与交接路径，不要求纯条件推演为了凑流程先发搜索。

1. 收集者实际取得并在获准位置保存原文或可复核片段，记录版本、章节/页码、适用范围与缺口，核对关键事实。检索摘要、萃取文本和生成报告都不能替代原文。
2. 调度器冻结并交接来源与核对结果后，另开 Astra 做证据辨析和推理加工，区分事实、假设、推断及未知。已有固定材料足够时直接进入推演，不重复收集。
3. 固定成果交 Luna 机械发布，随后显式交接独立 Astra 审核，再由合并子智能体执行精确版本门禁；作者自检不等于独立审核。

Research 只在既有任务授权、预算与实际缺口需要时可选用于找线索、补盲区，不是默认必经步骤，不作为事实证据。选用时仍配套 Search 定位原始来源，逐项对照报告、可见萃取与原文；未解差异不采信，材料不可见则明确缺口。无需为凑流程追加 Research，也不因它给出答案而省略原文。具体工具边界见[Tavily 协议](tavily-protocol.md)。

## 谁做什么，记录在哪里

- **用户**确定研究目标、授权与重要取舍。无需把人工在两个会话之间转发作为每个步骤的必经环节；实际接线未具备时如实报告，不能承诺实时自动推进。
- **Dot / 知舟（规划者）**守住总问题、阶段顺序、任务优先级和验收标准，对整体推进与用户沟通负责。具体派工、审核和 PR 合并交给子智能体，不因自己被细节吸走而丢失主线；收到影响目标或范围的异常时决定调整或交用户。
- **Chat Work 调度器**是常规任务分派与跟进入口：拆分已授权的有界单元，指派阶段执行者，控制依赖、预算与停止条件，读回实际产物并安排同 PR 返工；让负责人能查看知舟规划、Chat Work 调度和子智能体执行各处的进展与阻塞。实际通知和自动接线能力未知，不能由可见性推定已部署；未确认时人工补位。实质性研究判断另派 Astra，不能用调度器转述代替研究。
- **执行、独立审核和合并子智能体**按下表完成各自职责，建立分别可追溯的运行。作者/分析者/发布者不得审核自己的成果；机械合并不是另一道研究内容批准。
- **Dot / 知舟**负责目标、规划、优先级、验收与整体推进，不逐项承担机械执行。Chat Work 恢复为常规任务分派和跟进入口；若需要用户电脑文件、程序或本地插件，也可作为执行入口。直接委派仍须同样留痕。

Issue 是范围、负责人、依赖、预算/停止条件和验收的权威入口；PR 是候选差异、交接和返工讨论入口；`main` 是已采用版本。准备 Issue 前可用稳定的 `LOCAL-...` 标识，随后追加映射，避免两套状态。授权来自用户，不来自 PR 自报、标签或勾选。

继续遵守[参与者与步骤记录](agent-provenance.md)、[实验记录](experiment-protocol.md)及[审核记录](../reviews/README.md)：保留任务要求、实际执行者、请求及可见配置、规则/输入输出版本、实际操作与未知；没有进行实验不预填回合，不保存隐藏思维链，不为凑字段制造证据。

## 分阶段模型路由与交接

以下是本次采用的启动请求与职责，不是对后端模型身份的认证。最终审核的 `ultra` 为用户本次明确要求；Luna 合并执行只处理机械门禁。

| 阶段 | 请求模型 / 思考强度 | 工作与边界 |
| --- | --- | --- |
| 调度与流程控制 | `gpt-6.1-sol` / `high` | 拆分有界任务、指派子智能体、控制阶段/预算、核对交接并读回产物；实质性证据辨析与研究判断另派 Astra。 |
| 资源收集 | `gpt-6.1-sol` / `high` | 按关键问题用 Search 定位并核对原文、基本事实和口径，保留来源、缺失与失败；不因推演需要而补造事实。 |
| 证据辨析与推理加工 | `gpt-6-astra` / `ultra` | 另开子智能体，基于固定输入明确前提、逻辑链、方向与强弱、选择影响和改判信息；事实与推断分层。 |
| 机械整理与 GitHub 发布 | `gpt-6-luna` / `high` | 接收固定产物，做格式、路径、引用、差异/敏感内容自检及提交、推送、PR 准备；不新造结论、删反例或替作者实质修订。问题退回调度器。 |
| 最终独立审核 | `gpt-6-astra` / `ultra` | 与作者、分析和发布运行分离，核对任务目标、逻辑连接、事实使用、决策意义与精确版本；写回真实结果，不要求所有推断先逐环实证。 |
| 条件合并 | `gpt-6-luna` / `high` | 在已有独立审核基础上核精确 head、最终差异、检查、阻断和平台门禁，执行并记录合并；不重新裁决研究内容，不自行消解冲突或绕过门禁。 |

**只有一道最终独立内容审核。** 独立 Astra 对固定成果给出结论；Luna 合并者只核该结论适用于当前版本且其他门禁满足，不能把作者自检充作批准。平台要求的独立账户批准仍须满足。

阶段依赖为：Dot 确定任务目标与验收 → Chat Work 调度器派发必要收集/固定材料并跟进 → 另开 Astra 推演 → Luna 发布 → 不同运行的独立 Astra 审核 → Luna 条件合并 → Chat Work 调度器读回并汇总实际结果给 Dot，进入下一项已授权单元或报告停止原因。需要补证或实质返工时回到调度器，在同一单元授权和预算内安排，同一 PR 保留历史；不得由发布或合并者自行扩题。

角色切换建立新运行记录。分析作者不得兼任审核者；发布与合并即使用同一模型，也分别标记职责和实际运行，机械合并不能补上缺失的独立性。每阶段在同一 Issue 记录目标、输入版本、文件归属、依赖、预算、停止条件、交付对象及缺口；切换阶段不重置总预算。

启动前核对入口是否支持所需模型/强度，按[身份记录约束](agent-provenance.md)分别登记请求值、实际配置/运行报告值、来源和可核程度；配置、界面或 API 报告均不独立证明提供商后端实际身份。所需模型/强度不可用、报告与请求不符或必需条件无法确认时，报告实际可见值及限制，暂停依赖该条件的阶段，请用户决定替代或等待；不得静默降级。文档规定路由，不表示所有角色、工具权限、通知和自动交接已经部署或验证。

## 每个阶段的证据不能丢

交接沿用既有来源、运行、步骤和审核记录，不另造重型系统。每一阶段都保留并传递可复盘的证据链，摘要只能做入口，不能替代来源或覆盖前一阶段产物：

- **来源与取得过程：**保留获准保存的原文/附件或受控存放位置、来源链接、发布/访问时间、章节/页码及可取得的版本或内容哈希；记录适用地区、时期和对象。缺失信息与读取失败明确标记，不补造原文、日期或成功状态。
- **实际操作与产物：**保留脱敏的实际工具名、关键参数、结果/错误及其产物定位或哈希，区分计划、已发送、未发送、失败和结果不明；受控原始返回与可上传摘要分开。未实际调用的不记为已执行，失败后不以新摘要抹去失败记录。
- **分析依据：**保留可见的证据对照、冲突/反例、假设、推断、结论与限制等中间产物，以及结论→证据定位的映射；后续修订追加版本、理由及受影响主张，保留旧版本和审核/返工历史。记录简明理由与可核结果，不索取或保存隐藏思维链。
- **交接核验：**接收方核对输入版本、文件/证据清单、缺口及可访问性；收集→分析→发布→审核均不得只转述口头结论。发布前核对引用与原产物一致；缺件、无可追溯依据或审核者无法取得所需材料时明示盲区，不能宣称已核验或默默丢弃。
- **权限与隐私：**留存不等于一律上传 GitHub。原件、敏感数据、完整原始返回和内部日志按现有授权留在受控位置；仓库仅提交本批获准的脱敏索引、必要摘录、哈希/指针及产物。遵守版权与访问权限，不含凭据；向获授权审核者提供可用的受控访问或明确哪些本地未推送材料无法复核，不为便于审核扩大上传范围。

## 一个研究单元的最小交付

在 Issue / PR 中用短段落或链接说明，不新增重型系统：

1. 服务的未来十年学业/职业问题与当前选择，地区、时期、对象及不回答的范围。
2. 有方向、有强弱依据的判断；列明成立前提、逻辑连接、延迟和事实/假设/推断边界，不编造概率或精确幅度。
3. 对职业入口、竞争、培养路径或转向空间意味着什么；说明从行业到职业再到专业仍有哪些必要连接，不能一一硬映射。
4. 已有事实支持了哪一段，反例改写了哪一段；未知中哪些会改变选择、下一项应观察什么，以及何时应改判。
5. 实际过程、产物版本、检查、偏差、返工与停止原因。实验输出与审核合并分别记录，合并不能充作现实验证。

**与原推演方向不同也是有效收益。** 只要能定位需修正的前提或连接、识别后续信息需求并更新下游判断，就不是失败。负面结果和保留未知可以采用；不能为通过审核拼肯定结论，也不能用无穷核查回避合理的方向判断。多个模型一致不是独立事实证据，PR 数量和形式完整不代替研究质量。

## 显式交接与状态

1. 执行中保持 Draft；普通提交、CI 成功或 Ready 状态不自动等于有效交接。
2. 自检完成后，由调度器或执行者在 **PR 正文**写入：
   `ready for independent review | head: <完整提交SHA> | handoff by: <实际运行标识> | reviewer role: Astra Ultra`
   退出 Draft 后进入待审；无法退出 Draft 则报告阻断。旧 `ready for Dot review` 标记作为历史交接保留，新任务采用上述角色标记。它是人读记录，不是已安装触发器，也不是批准。
3. 审核子智能体重读当前 head 与任务边界；SHA 不符、仍在编写或 Draft 未解除时退回交接，不自动审核。
4. 实际审核评论写明：
   `Independent review | head: <完整SHA> | reviewer run: <实际运行标识> | verdict: 建议采用 / 需修改 / 证据不足`
   附基线、范围、依据、未核事项、逐条阻断/非阻断及返工验收条件；签名是角色归属声明，不是密码学签名。
5. 调度器读取结果，需修改时指派执行者在同 PR 逐条回应、更新完整 SHA 并重新交接；独立审核复核变化及受影响主张。Chat Work 调度器负责读回和跟进；未确认可用的通知或自动触发时由人工补位，不得假称已存在。
6. 通过审核不等于已合并。合并子智能体执行下述门禁；完成后调度器记录合并提交和仍未解决的决策问题，Dot 负责接续规划。没有已授权下一单元时不得无限派工。

不对未变版本反复审核。新提交不继承旧 head 的批准，旧结论保留；基线变化或冲突解决影响内容时复核受影响部分，不能只看新增行而漏掉被推翻的结论。

## 审核归档与精确版本合并

PR 签名评论是即时反馈；按既有规则把实际审核归档到 `reviews/<任务号>-rN.md`，保留历史并链接原评论。冻结成果 H 后，仅追加真实审核记录 R 可由协调者提交，得到最终 head F；不得借归档夹带正文修改。合并者核对 H→F 仅有该记录且内容忠实，留下绑定 F 的最终核验评论。若还有任何其他变更，重新审核对应内容与受影响主张并绑定新版本。不得为在审核文件里写入包含自身的 SHA 而无限改提交。

用户于 2026-10-23 调整职责：独立审核子智能体写回实际审核，合并子智能体执行已获授权的条件合并；Dot 负责规划与整体推进，不再逐项亲自审核和合并。明确交接的 PR 必须在以下条件**全部满足**时才能合并，不需仅因换版重复请求同范围授权：
- 在用户授权范围内，当前 head 有有效审核与最终核验；作者没有审核自己的成果。
- 无未解决阻断；非阻断项有明确处置；检查缺失、失败、运行中或不明均不得视为通过。
- 当前精确 head 上指定的 `.github/workflows/validation.yml` 成功，且平台要求的其他检查/批准均满足；无冲突，基线影响已核对。
- 合并前重新读取 head、base、检查及阻断状态，以预期完整 head SHA 执行合并；发生版本竞态则停止并重新核验。
- 尊重实际分支保护和平台限制，不能管理员绕过、降低门禁或假称存在/通过了无法读取的保护。历史“无保护”记录不代替合并时核验。

调度器、执行者、审核者、合并者和 Dot 可能共用同一 GitHub 身份。不同角色、模型或运行ID不证明不同账户，也不单独证明独立。若平台禁止正式自审，可用诚实的角色签名评论记录实际独立运行的研究审核；**评论不等于 GitHub APPROVE，也不能替代规则要求的独立账户批准**。缺该批准就保持未合并并报告；不切账号、改权限或绕过保护。

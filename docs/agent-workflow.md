# 多 Agent 协作与自动推进

用户于2026-10-19授权：同一已授权任务内，审核通过继续下一步，不要求逐版人工确认；未通过回到修订或补证，再独立审核。授权不扩展到原学业库上传、仓库公开、凭据操作或无关任务。

## 各种载体的职责

| 载体 | 权威内容 |
| --- | --- |
| Issue | 任务范围、负责人、依赖、预算、状态与验收；协调者按人的请求登记授权 |
| 独立分支与工作区 | 候选成果；执行 Agent 不共用同一可写工作区 |
| PR | 候选差异与交接入口；Draft/Ready 不等于批准或授权 |
| `reviews/` | 固定版本的独立审核、问题、未核项和复核历史 |
| 协调者本地登记 | 人的授权依据、允许路径、实际审核运行及精确版本；不得从PR自报通过自动生成 |
| `main` | 已授权、经独立审核且检查通过的版本 |

Issue建立前可用[任务模板](../templates/research-task.md)准备，建立后仅维护Issue正文，其他记录引用它。仅历史首次提案使用ARCH-001；后续均关联Issue。协调者在本地保存本次授权范围，Issue后来编辑不自动扩大允许路径。

## 角色

执行Agent修改候选成果并自检；另一次未参与编写的Agent运行负责审核。协调者核实真实审核回复和证据范围，登记结果并运行[自动控制器](review-automation.md)。审核建议通过不等于任务授权；作者修改审核文件、勾选PR清单或写“通过”均不能自动放行。

负责人给出目标与边界，无须逐版批准。正常修订、复核与合并在此边界内自动继续；超范围、凭据/访问阻塞、预算不足或反复无法解决的问题才升级给负责人。不同模型名称不证明独立；共享GitHub身份和本机账号仍是共同信任域。

## 状态和推进条件

| 情形 | PR状态 | 下一步 |
| --- | --- | --- |
| 执行中或缺少有效独立审核 | Draft | 完成自检、交接并调用审核Agent |
| 审核要求修改、存在阻断或自动检查失败 | Draft | 自动返回执行者修订，随后重新审核 |
| 证据不足 | Draft | 在授权内补证或收窄主张，再审核 |
| 新内容提交或审核记录无法核验 | Draft | 旧审核失效，核对新版本并重新审核 |
| 基线推进或冲突 | Draft | 同步基线、处理冲突、重新审核 |
| 有效独立审核通过，自动检查尚在运行 | Ready | 等待检查；不合并 |
| 有效审核、零阻断、授权路径、版本及自动检查均满足 | Ready | 控制器重读状态，以精确head执行合并 |
| 已合并 | 保持已合并 | 完成任务，继续已授权队列；重复运行不重复合并 |

Ready表示已具备交接条件。允许合并还要求当前base/head与登记一致、审核后只新增经核实的那一份审核记录、指定工作流对当前head成功，以及没有冲突。非阻断建议必须有明确处置，不用非阻断标签掩盖实质风险。

“退回”指工作状态退回，保留Git历史，不重置或删除已有成果。合并后发现问题另建修复PR，不能强推抹除历史。

## 并发、依赖与恢复

分派写清执行/审核角色、基线、文件归属、依赖、工具、预算与停止条件。依赖或写入范围重叠的任务串行；独立任务可在预算内并行。共享受限工具仍按其协议串行。交接必须包含实际产物、版本、检查、未完成和阻塞原因。

中断后先核最后提交与现有PR，撤销原写入归属再转派。上游草稿不当定论；基线变化、冲突解决及正文修订均重新绑定版本。所有自动合并通过同一协调主机的控制器锁串行执行。外部管理员直接改主分支仍可绕过，这是无服务端保护时的限制。

连续两轮修订仍出现同一未解决问题时，停止重复派工并升级；额度不足等待恢复，不循环启动昂贵模型。没有已授权、可推进任务时不启动Agent。具体后台运行方式及本地状态见[自动化说明](review-automation.md)。

# 交接机制试验收口：先固定规则，再观察实际执行

2026-10-25｜关联 [Issue #71](https://github.com/mythpan1/pathwise-research/issues/71) / [PR #72](https://github.com/mythpan1/pathwise-research/pull/72)
作者：知舟主会话直接整理。此为脱敏结果和决定摘要，不是原始运行日志、独立审核或部署证明。

## 1. 决定与边界

用户在本轮讨论中指出：自写执行凭证不能证明执行；新增检查者又会产生“谁检查检查者”的无限递归。最终决定先定规则、观察实际问题，随后要求继续收口。
因此停止扩建门禁、增加审核角色和继续原型修复。保留已有负面结果，不以更多流程设计占用研究主线。
“观察”指后续已授权任务中的记录与复盘，不创建定时监控，不自动启动下一研究或视频 13–15。PR32、PR70 不在本次修改范围。
这次仅修订 PR72 文档，不修改现行主流程、代码、权限、凭据、hook、CI 或账号；未合并、未部署。旧独立审核不覆盖本次新增正文。

## 2. 最小协作规则

这些规则适用于知舟直接执行、Chat Work 调度和子代理执行，不因身份不同而豁免；具体任务仍以用户最新授权为准。

1. 开工明确任务、目的、输入固定版本、范围、交付和停止条件。主线仍为政策、产业变迁、人口结构变化，服务未来十年的学业/职业选择。
2. 每环交接保留输入输出定位、版本/实际可取得的哈希、证据清单、缺口和下一责任人。摘要作为入口，不替代原材料；不得补造记录。
3. 接收方自行取得并核对所需产物。执行者自写的“已完成”、自填身份、耗时或 PASS 文件均不是独立执行证明。只有自行核验过的部分才能记已核验。
4. 机械检查验证文件全集、字节一致性、版本和前序依赖；保留实际检查结果。没有受保护的执行入口和记录，就只称可审计声明或协作级检查，不称不可伪造凭证。
5. 一道独立内容审核绑定明确成果版本，给出具体材料位置、简明判断理由、阻断和未知。作者自检不是独立审核；不索取或保存隐藏思维链，也不靠再增一个审核者证明前者认真思考。
6. 哈希证明字节一致，不证明认真阅读、来源真实或推理正确。内容验收依靠可复核成果、关键节点抽查及反证；抽查范围和未覆盖部分必须说清。
7. 内容或输入实质变化后，旧审核不能自动套用；只复核受影响部分。合并核验是机械采用条件，不再做一轮重复研究审核；没有有效审核或合并授权就停在待审/待采用。
8. 执行过程未被独立观察时标为“过程未验证”；无法取得原材料标明受限范围。保留失败、绕过和未知，不用事后自述追认全过程成功。
9. 后续授权任务若发现漏步，记录发生环节、实际影响、已有证据和最小修正；不预建新角色、全套自动化或固定周期巡检。

记录尽量复用当前 Issue/PR 和现有模板，不强制每条规则对应一个文件或一次提交。原始日志、机器路径、身份隐私及凭据不上传。

## 3. 已完成试验与结论

试验均在获准隔离本地范围内完成。下表不是对 GitHub 生产入口的攻击测试，也不是所有设计条目的验收。

- 离线原型最终轮：37 项预期满足（31 项预期拒绝，6 项正常/状态断言）。使用模拟信任存储与身份，不能证明真实访问隔离。
- 固定 GitHub 材料影子核验：PR72 的设计和审核归档，在 F=bc2fccc4888b027b045b19a22ffc429a52a8429d 分别取得两次原始字节；独立取得副本的字节/哈希及 Git blob 对照一致。四种副本篡改测试被拒绝。
- 角色模拟：原型中硬编码 analysis.txt 导致首个正常路径 KeyError；在新副本修正为任务指定路径后，17 项模拟通过。真实材料读取不等于已完成内容独立审核；模拟 parent/child 标识不证明真实认证身份。
- 绕过试验：22 项观察中，14 项被拒绝、8 项绕过成功。程序退出码 0 只表示观察符合测试预期，绝不表示保护通过。此轮未修复；试验前 261 个文件未变。

成功绕过的八项归类：
1. 清空分派/接收绑定后绕过外层封装，直调底层可推进至 APPROVED。
2. 过期分派绕过外层后仍可进入 RUNNING。
3. 接收来源登记缺失时直调底层仍可进入 SOURCE_RECEIVED。
4. 同进程改写必需清单、锚点、收据和审核等模拟可信输入，普通封装也可到 APPROVED。
5. 不经过门禁直接写本地最终状态文件成功，但内存状态并未相应完成。
6–7. 父/子两种角色冒用另一角色，外层拒绝，但直调底层各可进入 RUNNING。
8. 调用者伪造前序 APPROVED 状态，可直接得到 ADOPTED_SIMULATED。

仍能阻断的例子包括：保留旧锚点而修改正文、旧任务事件版本、通过封装跳过必需阶段、部分伪造 PASS 文件情形。这些成功检查不抵消上述入口及信任边界缺陷。

结论：检查逻辑在被调用时可以有效，不能据此断言检查不可绕过。当前原型不具备生产强制门禁资格；未证明真实 GitHub 或实际认证父/子身份遭到绕过。没有执行真实合并、权限调整或服务端保护测试。

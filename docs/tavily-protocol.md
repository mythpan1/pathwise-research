# Tavily：证据核验与调用边界

这是本项目使用 Tavily 的通用操作与验收规则（2026-10-22）。与[研究框架](research-framework.md)、[协作流程](agent-workflow.md)及[归属记录](agent-provenance.md)配合使用；不是工具实现或接口文档，也不授予新的研究、调用、账号或修改权限。

## 默认工具与使用经验（2026-10-23）

Tavily 是默认 Search 工具，Exa 作为备用，不为每次查询同时双查；是否启用备用仍服从任务授权、预算、适用守门和错误停止条件，不借备用绕过限制。用户表示已使用 Tavily 数月，并确认每个 key 都有额度；这是用户经验声明，不是本轮逐 key 验证，也不推出固定余额。按用户要求，不逐 key 探测、不额外查余额。

[Issue #20 结果](tavily-acceptance-result.md)记录了首次 Search 失败与修复后一次最小验证成功；Research 仍未验收。默认工具选择不把未验收能力当作已通过，也不为正常使用重复冒烟测试；版本、路径变化或新故障时按[验收计划](tavily-acceptance-plan.md)针对受影响部分复核。

## Research、Search 与原文怎样配合

- Research 的综合报告先作为候选结论和线索，不能因为有引用、萃取文本或流畅叙述就直接采信。Search 摘要和萃取结果也不是原文真实性、完整性或含义的保证。
- 使用 Research 的本轮任务，应配套 Search 定位关键主张的原始来源，再实际核读原文。逐条对照 **Research 的提炼、可见的萃取内容、原文**：数字与单位、日期、地区和对象、统计口径、条件、否定/例外、因果与相关、计划与实际。萃取内容不可见或原文不可取得时记明缺口，不假称已经完成三方核验。
- 关键主张经原文支持、适用范围和限制核清后才采用；有出入则保留各版本及具体差异，修正或暂不采用受影响主张。不能用 Research 与 Search 彼此一致替代原文检查，也不能为得到一致答案反复重跑。
- 两种工具引用同一原始来源，或多站转载同一材料，都不算多份独立证据。原文只能支持其实际陈述，不自动证明因果或普遍性；需要独立佐证的主张仍另核来源独立性。
- “同步”指同一研究单元内配套核查，不要求同时并发；共享额度池继续串行使用。普通 Search 足以解决问题时，不为凑流程追加 Research；也不重复已核且版本/适用范围未变的原文。
- 在已批准范围和预算内安排核查；原文访问失败、工具能力不足或预算不够时，交回未核主张和缺口，不自行扩大查询、换模型或升级 Research 档位。

最小留痕可以直接放进既有证据卡/来源索引：主张、Research/萃取的版本或不透明证据ID、原文链接及段落/页码、核对差异、采用/修正/待核状态、核查者与时间。无需新建数据库或重复保存整份原始输出；原件、完整日志和敏感材料继续遵守上传边界。

## 从哪个入口调用

1. 沿用本任务**已获授权且已核实**的 wrapper/工具入口及原生额度守门。派发时记录入口名称、可核版本/配置依据、实际操作类型和预算；未知写 unknown，不拿历史全局配置代替当前入口证据。
2. DSH 原生 Tavily 沿用其守门工具；其他已授权入口也必须保留适用的原生守门。不能为了省一次额度检查，改成直接请求API、关闭检查、换未核入口或人工处理凭据。
3. 本文未独立核实实际安装源码、统一命令路径、状态码映射和当前轮换实现，故不虚构操作命令。PR #15 的内部注册/直接调用是当次留痕，不是所有智能体的默认接入方式。入口不明时先只读核对已有说明、安装源码或既有回执；只读核对也须在获准环境和文件范围内，不用额外余额探测代替代码核对。
4. 文档约束不等于工具已经实现。若实际守门行为与最新用户要求冲突，停止相关调用并报告具体冲突，另行确定修复范围；不得自行修改脚本、禁用守门或绕过限制。

## 额度和错误怎样处理

- **不在工具外额外叠加每次搜索前后查余额、周期轮询或失败后连续探测的循环。** 不为记账而反复调用 quotaSnapshot；原生入口本身已有的检查不因此取消，也不把旧个案中的附加前后测固化为新默认。
- 业务请求明确返回额度不足时，仅按已核实、已授权的既有 wrapper 轮换规则处理，并在受控本地保留必要的匿名槽/尝试及结果；发布索引不含槽位标识。本文不扩充账号池、不授权人工切换凭据，也不改变既有的串行共享池约束。
- 余额查询失败、空值或 unknown **不等于额度不足或耗尽**。不得据此盲目轮换；限流、网络失败、超时、鉴权失败也须与额度不足区分，不切账号或换入口绕过服务限制。原因不可见就保留未知，不猜测具体HTTP状态。
- 原生守门返回不可用、停止或预算不能确认时，遵守停止结果；先看现有返回、日志和代码，不能把再次实时探测作为默认排障步骤。确需新诊断、重试或修改时，另行明确必要性、授权和边界；服务要求的等待/重试限制继续有效。
- 无论是否轮换，任务总预算和停止条件不重置；查询/读取/Research提交、轮询、失败与重试按实际动作分别记录。对结果不明的提交先查既有回执，不能当作未发送后重复提交。

## 费用与审核

预算预留、观察到的余额差和实际账单分别标明；余额没有变化不等于免费，余额未知不写0。模型积分与搜索额度不混账。计划、已发送、成功、失败和未知分别记录；不能仅凭没有结果文件断言没有执行。

审核者核对关键主张与原文、差异处置、调用归属/次数、停止原因及未核事项。审核通过只覆盖已检查的成果和边界，不证明未读取的本地日志、实际扣费或 wrapper 正确无缺陷，也不自动启动下一单元。定时巡检已暂停，事实与当前协作权限见[协作流程](agent-workflow.md#授权的流程不等于已经自动接线)；本规则不恢复自动化。

# 江苏招生与职业规划：知识单元和组合契约

版本：2026-11-01；任务准备标识 `LOCAL-20261101-planning-framework`。这是[高考规划总入口](gaokao-planning-core.md)在[完整研究框架](research-framework.md)上的接口细化，不是第二套知识库、数据完成声明或软件设计。采用状态由本轮 PR 和独立审核记录维护。

## 1. 目标、取舍与边界

让 Agent 从江苏考生当年可报条件出发，以可复核的年度院校专业组连接具体培养、职业入口及政策／产业／人口情景，提出当前倾向、备选和改判条件。上端仍可覆盖全国与相关地区，学校范围是全国在江苏招生院校，不是仅江苏高校。

采用的方案是在既有研究目录与判断／来源模板上加薄接口，不搬迁历史正文、来源或审核。另起数据库／图谱软件会扩大范围；只添导航又不能约束组员完整性、跨年比较和关系适用性，因此本轮选择文档契约、一个扩展模板及合成验收。字段可内嵌现有文件，不要求每个对象各建文件。

本轮不批量采集、填入真实招生记录或进行新的行业研究；不上传会员 CSV、个人资料、完整原件或内部日志，不改变主流程、权限、CI、自动化和审核角色。设计完整、真实数据覆盖、情景现实验证与软件实现分别验收。[协作主流程](agent-workflow.md)及最新用户指示决定执行，旧版框架中的历史角色安排不另成一套流程。

## 3. 八类最小知识单元

一个单元是可独立引用并注明边界的对象或判断，可位于文档小节。用“类型／对象键@修订版本＋固定提交与路径/锚点（或受控内容版本）”定位。现有链／判断标识继续有效，增加类型索引即可；标识不是新的全国编码标准。

| 类型 | 身份与最少专有内容 | 输入 → 输出 / 不能推出 |
| --- | --- | --- |
| `GROUP` 年度院校专业组 | 生源省、招生年、科类、渠道、批次、轮次、学校实体与当年学校代码、组代码；计划版本；**完整成员**及各自专业/方向代码、校区、学制、收费、选科与其他限制、计划数；成员总数及完整性核验 | 年度正式计划及修订 → 当年组实例和成员清单；组投档线不等于每个专业录取线 |
| `RULE` 年度适用规则 | 规则发布主体、适用省年/渠道/批次/轮次/院校，作用阶段；条件、例外、生效/废止及更正关系 | 正式规则 → 资格、投档、分配或退档后的条件约束；一条省级规则不能补齐各校例外 |
| `CHANGE` 跨年变化与可比性 | 前后两个或多个年度对象版本；一对一/拆分/合并/多对多映射；逐成员与计划、选科、校区、费用、批次差异；数据是组投档还是专业录取 | 历史数据＋当年条件 → 可比/需调整/仅参考/不可比及理由、剩余偏差；不凭组号相同拼序列 |
| `ACCEPT` 考生私有组接受度 | 不透明考生标识与个人条件版本；目标 GROUP 精确版本；每个可能分配成员的**接受/条件接受/不接受/未确认**、理由；条件表达式、满足/不满足/未知及依据；调剂选择与失败后备选 | 公共完整组＋私有约束 → 按 3.3 聚合整组接受度和调剂情景；条件未成立不能算可接受保底，个人判断不写入公共事实 |
| `SCENARIO` 宏观及就业情景 | 连续链与判断版本、主线归属、目标地区/就业年份；基准与有区别分支、前提、传导主体/时滞、方向与强弱依据 | 政策/产业/人口机制 → 工作量、组织响应、任务与供需变化；产业产出增长不直接推出新人岗位增长 |
| `ENTRY` 职业入口 | 职业/任务及组织、地区、目标年份；新人招聘与在岗/存量分开；能力、实际筛选与资格、竞争、成长、可迁移出口 | 情景＋职业依据 → 某类毕业生可能进入的路径与条件；不能从行业标签直接映射专业优劣 |
| `TRAINING` 院校具体培养与资格 | 学校、校区、项目/专业/方向、入学届别、培养版本、学制与证书；实际可获得课程实践及门槛；升学/转专业/执业资格分别注明 | 学校届别材料＋资格规则 → 获得训练与接近职业入口的条件；校级资源不等于所有学生可取得，毕业不等于取得执业资格 |
| `PATH` 组合路径 | 公共群体或私有考生；候选 GROUP、ACCEPT、TRAINING、ENTRY、SCENARIO 等固定版本；报考/培养/毕业/就业时间轴；主备路径及共享前提 | 下端条件＋上端情景 → 当前倾向、理由、招生与职业两类风险、代价及改判点；不是录取承诺或长期就业保证 |

### 3.1 年度身份与组员完整性

`GROUP/JS/<year>/<category>/<channel>/<batch>/<round>/<school-key>/<group-code>@rN` 是可用示意；实际记录须同时保留来源中的年度代码。学校实体键与各年招生代码通过映射连接，学校更名、合并、分校区或办学主体差异不能靠名称自行合并。非组制渠道记录其实际志愿单位，不制造虚构专业组。

换招生年就产生新的组实例，即使组号、校名和成员看起来相同。年内计划更正产生新修订，保留旧版及变化原因；跨年用 CHANGE 连接，不沿用同一年度组身份。专业目录代码还须注明目录版本；相同名称不同方向、校区或收费不能静默去重。

完整性至少核对来源版本、预期成员数与实际列出成员数、是否包含全部页/附件、重复或遗漏、组总计划与成员计划的可加总口径。计划未逐专业分解时明确不能做加总验证，不编数字。成员状态为 `complete / partial / unknown`；后两者不能认定全组可接受或有效保底，但可以保留已知成员及组级条件候选。受限原表不复制到仓库，摘要完整性核验在获准受控位置完成。

### 3.2 所有单元的共同字段

沿用[判断及改判模板](../templates/research-judgment.md)、[来源模板](../templates/source-record.md)和[连续链模板](../templates/research-chain.md)，用[规划单元扩展模板](../templates/planning-knowledge-unit.md)承接，不重新编号旧来源。

| 字段组 | 最低要求 |
| --- | --- |
| 身份与定位 | 类型、对象键、修订、前版、所属链/判断、固定内容定位；来源命名空间不可省略 |
| 适用对象与地域 | 生源省、学校/校区所在地、就业地区分别记录；省年/类别/渠道/批次/轮次/学校/专业/届别等按类型填写。不适用写明原因，不能用空白充当全国通用 |
| 时间 | 来源发布日期、实际查阅/核验时间、规则生效范围、数据所属年、入学届别、目标毕业与就业时点分开；未知写未知，不把记录日当有效期起点 |
| 依据与类型 | 按重要主张区分来源陈述、经核事实、假设、推断、建议/个人取舍；来源原文定位及版本/可用哈希；来源支持哪一段、未支持哪一段、反例和冲突。一个单元可含多类型，不整体贴“事实” |
| 生命周期与适用判断 | `draft / usable / needs_review / superseded / withdrawn`；`usable` 只指可在注明条件下使用，不是事实认证或正式批准。对某次查询另记 `matches / does_not_match / unknown` 与理由；冲突保留双方版本及受影响主张，必要时暂停无条件采用 |
| 依赖与更新 | 上下游单元及关系的精确版本、关键共同前提、下一观察/事件、复核截止或使用前检查、变更原因及受影响输出；“长期有效”也须给复核触发 |
| 权限与覆盖 | 公开/获准仓库摘要/受控来源、允许用途与输出范围、可访问性、已覆盖对象与缺口；无权限与无数据与不满足资格分别标记 |

规则过期、尚未生效或关键冲突不能无提示当现行规则；历史版本仍可用于解释当时决策。来源已核不等于所有推断已证实；核验时间新不等于数据年份新。

### 3.3 ACCEPT：声明四态、条件核验与整组聚合

成员的**接受度声明**固定四态：`接受 / 条件接受 / 不接受 / 未确认`，与本次条件核验结果分开保存。条件接受须写可核条件表达式、条件涉及的对象/版本/有效期、核验依据与时间、下次复核触发；多个必要条件默认均须满足，允许择一的条件须明确逻辑，不能暗中改成“满足一项即可”。无法核验的未来承诺（如必然转专业）不能标为已满足。

| 成员声明及条件核验 | 本次有效接受判断 | 保留方式 |
| --- | --- | --- |
| 接受 | 可接受 | 不替代资格、投档与培养风险核验 |
| 条件接受，所需条件已核满足且仍有效 | 在已列条件下可接受 | 声明仍为条件接受，不能抹去条件改成无条件接受 |
| 条件接受，条件表达式已知不满足 | 当前不可接受 | 可留待条件改变的情景，不计当前有效保底 |
| 条件接受，条件是否成立未知；或声明未确认 | 当前未确认 | 保留缺口，不能默认为接受或已满足 |
| 不接受 | 当前不可接受 | 不因组投档较稳改变个人声明 |

**整组结论按以下优先级聚合所有按适用规则可能分配的成员（可能分配范围不明时不能擅自排除成员）：**①存在不接受或条件已知不满足的成员，整组为“当前不接受”；②否则，成员不完整、存在未确认声明或条件未知，整组为“未确认”；③否则，存在条件接受成员且其条件均已核满足，整组为“条件接受（当前条件已满足）”；④仅在完整成员均声明接受时，整组为“接受”。成员偏好声明保留，整组“当前不接受”不把原来的条件接受永久改成拒绝；缺失与不满足不能互相替代。

**保底规则：**只有整组“接受”，或“条件接受且当前全部条件已核满足并在使用时有效”，才可继续检查是否具备招生端有效保底条件；后者须明确标为带条件候选而非无条件保底。资格、投档估计及分配风险仍须分别通过相应判断，接受度本身不保证录取。条件未满足/未知、成员未齐或存在不接受成员时，不计为当前有效保底，但可保留情景候选。条件后续失效、证据过期或偏好变化时，立即标 ACCEPT 与依赖 PATH 待复核，重聚合并暂停沿用原保底判断，保留旧版。

## 4. 连接也是带条件、带版本的知识

一条关系至少包含：关系标识/修订、两端单元与版本、关系类型、主体和机制、适用省份/地区/年份/届别、成立条件及例外、证据及事实/推断类别、时滞/转换成本、未知或反例、生命周期及更新触发。可内嵌既有依赖表，不要求建立图数据库。

| 关系类型 | 允许的连接 | 必须保留的条件 |
| --- | --- | --- |
| `governs` / `member_of` | RULE 约束组/路径阶段；成员属于年度组 | 适用阶段与省年轮次；成员只属于该年度计划版本 |
| `comparable_to` / `reorganized_from` | CHANGE 连接历史与当年实例 | 映射证据、组成差异、可比性等级及偏差，不传递“同组号=同对象” |
| `acceptable_for` | ACCEPT 覆盖某个 GROUP | 私有条件版本、成员完整性与逐成员接受结果；规则不明的分配空间不得缩小为已报专业 |
| `enables_training` / `requires` | 组成员接 TRAINING；TRAINING/ENTRY 接资格规则 | 入学届别、实际资源取得、资格/考核/费用与时间；必要条件不等于充分条件 |
| `may_enter` / `affected_by` | TRAINING 接 ENTRY；ENTRY 接 SCENARIO | 能力证据、雇主筛选、新人入口、目标地区年份、成立条件；不得把条件路径写成必然职业 |
| `alternative_to` / `shares_dependency` | PATH 的主备关系及共同依赖 | 触发切换条件、资格/成本/窗口；共同付款方、预算、技术路线、地区需求等，不能因职业名不同就叫独立保底 |
| `supersedes` | 新版替代旧版 | 改变内容、原因、有效区间和待复核后继；不删除旧版 |

上下端汇合的最小链：`当年条件 → RULE/GROUP → ACCEPT → TRAINING → ENTRY ← SCENARIO`，由 PATH 汇总。关联失败留缺口；允许多对多、有区别分支与跨期反馈，不把推断回填成支持自身的独立证据。

## 5. Agent 按需检索与输出协议

这是人工/Agent 可执行的文档步骤，不宣称已部署检索器。优先读匹配单元，遇缺口只补会改变资格、排序或关键方向的信息。

1. **固定请求。** 明确江苏生源、报考年、科类/选科、渠道、成绩/位次及是否模拟；学校地域限制与目标就业地区分别记录；确定个人资料用途权限。其他生源省请求标明本阶段数据未覆盖，不能套江苏规则，亦不直接判为不可报。
2. **取年度规则与候选。** 筛省年/类别/渠道/批次/轮次及生效范围，核实际在江苏招生的计划，再取年度 GROUP 完整成员。未知资格、未找到计划、未获得权限分别保留；证据明确不符合才排除。
3. **取可比历史。** 经 CHANGE 检查组构成、选科、计划、校区和规则变化，区分组投档与专业录取。只有分数时按同年同类一分一段得到可能的同分位次区间，不将区间端点当唯一考生次序；缺同分细项时用边界分支。不能可靠映射的历史仅参考，不进入同一精确趋势。
4. **构造招生阶段判断。** 在当前条件下估计梯度和志愿顺序，而非等待真实结果；资格、投档、专业分配、退档/征集/下一批次分别输出（见下表）。缺专业数据仍可给组级方案、条件分配情景及关键缺口，不编精确录取概率。
5. **叠加私有接受度。** 逐个记录接受/条件接受/不接受/未确认；对条件接受另核条件满足/不满足/未知、证据有效期，按 3.3 聚合整组并比较服从、不服从及换组。条件未满足或未知、存在不接受/未确认成员或成员未齐时，不计当前有效保底；条件已满足也保留条件标签和复核触发，不能变成无条件保证。不能用“入校后必转专业”消掉风险。
6. **双向召回，在入口汇合。** 下端从江苏当年可报且可接受的 GROUP 成员召回多个可能 ENTRY，不把专业锁成单一职业；上端独立从政策、产业变迁、人口结构的相关连续机制及不同 SCENARIO，追到受影响任务、用人组织和新人入口，再反查哪些候选能连接。两路在同一目标地区/就业时点交叉比较，不只替已有专业找支持。TRAINING、学制与资格作为已核事实或明示条件搭桥，仅补会改变当前选择的部分，不把入学后学习安排当主要推演；行业产出、任务工作量与新人岗位分开判断。跨地区/年份或资格桥梁不足时保留条件与缺口，不冒充已可进入。
7. **同情景跨候选比较，形成当前判断。** 在相同地区、年份和情景前提下比较各候选可接的多个入口，再比较情景改变后的顺序；输出当前有方向的条件建议、理由、风险、备选、转换代价和明确反转信号，不因待核而全部搁置判断。按真实可接受顺序组合方案，招生风险与培养/职业风险分栏，不以某一端优势抵消另一端硬约束；检查主备共同付款方、预算、技术和资格依赖，不将不同专门资格互认，也不输出伪精确总分。
8. **返回可追溯结果。** 列明读取单元及版本、排除对象与原因、条件候选、未覆盖范围、来源访问限制、关键缺口优先级，以及会改判的触发和下一复核时间。检索命中集合不等于全量可报集合；若覆盖不足，明确排序只在已比较集合中成立。

| 招生阶段 | 输出 | 禁止混同 |
| --- | --- | --- |
| 资格 | 满足/不满足/待确认，所依赖规则与缺项 | 未确认≠通过；无数据≠不符合 |
| 投档 | 可比历史和当年变化下的相对梯度、情景；真实投档状态另列 | 历史最低线≠当年保证；估计≠已投出 |
| 专业分配 | 目标专业机会、可能调剂成员及接受度、学校条件 | 进档≠进入目标专业；服从≠无条件不退档 |
| 退档及后续 | 未投出/已投出后退档分开；当年规则允许的征集/后续批次、状态资格、时间和计划 | 不假定本轮退档后继续检索其后志愿；未公布或已错过窗口≠现成保底 |

**最小输出包：** 请求与覆盖边界；固定版本清单；候选及四阶段表；培养—职业—情景条件链；推荐顺序与主备共同风险；“事实/推断/建议”标识；优先缺口和改判条件。只提交获准内容，个人方案不因有公共单元就可公开。

## 6. 变更、权限与停止条件

年度新计划、成员/选科/费用更正、学校规则/资格变更、历史映射修正、培养资源变化、职业筛选或关键情景前提变化、考生条件/偏好改变、填报窗口将至，均可能触发复核。

处理顺序：保留新旧来源 → 创建受影响单元/关系新版本 → 列出所有直接与间接依赖的 PATH/ACCEPT 等 → 标记 `needs_review` → 重算受影响阶段及排序 → 核对仍可保留的独立分支 → 记录理由并按原流程审查采用。共享支付或制度前提也要传播，不能只遍历表面职业名称。已发报告须提示已知失效部分；历史预测不回写成事后正确结果。

受限数据的索引、摘录、派生表、缓存、日志和最终输出继承相应访问及用途边界，不能因为转成摘要/哈希就默认可上传。仓库仅保留当前批次获准的必要方法与脱敏指针；个人接受度和成员原表在受控位置由有权限者使用。审核者缺少源材料访问时明确未核范围，不为方便独审扩大权限，不把哈希当真实性证明。

资格硬条件、来源冲突或覆盖不足时，停止的是无依据的无条件结论，不是全部规划：继续给受限制的候选、条件分支和最值得补查事项。需新付费权限、个人资料授权、跨省数据建设或软件开发时停止依赖该扩展的动作，交负责人决定。

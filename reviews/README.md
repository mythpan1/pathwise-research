这里存储研究与架构成果的审核依据。PR 是提交与讨论入口，本目录提供可追溯的审核记录；当前由独立审核子智能体审核、调度器登记交接、合并子智能体按门禁执行；[旧控制器](../docs/review-automation.md)是独立历史实现，本次不启动。

## 审什么

1. **任务与范围**：是否回答约定问题并返回未来十年学业/职业选择的影响、推演路径和改判信息，而非只完成局部核查或形式记录；文件和上传是否在授权内；研究对象、地区、时期是否一致。
2. **证据与推断**：主张能否回到原文；政策历史、适用性、口径与时效是否核验；是否把假设或相关性写成事实、因果和预测。
3. **职业连接**：人口、政策与国际因素是否经过主体、资源、任务和供需传到职业；是否混淆产业增长与新人岗位，或混淆在岗人数与招聘。
4. **反例与不确定性**：是否识别能改变判断的其他解释；老龄化不只研究养老，少子化不只教育且不预设教培放松。反证能否定位失效前提或连接并提出后续信息需求；假想抵消不与有依据的基准自动等权。未逐环实证不单独构成阻断，关键前提/逻辑断裂、事实冒充或超范围断言才须修订或收窄。
5. **交付完整性**：版本、链接、图示、复现材料与未完成项是否清楚；并发成果是否存在冲突。

架构提案可以只审方法一致性与流程可执行性，但必须明确未做现实政策、统计和行业实证。不能用“架构审核通过”替代“研究结论已验证”。

## 记录和结论

使用[审核模板](../templates/review-record.md)，文件命名为 `<任务号>-r1.md`，复核使用 `r2` 等新记录并链接前版。保留原结论，不覆盖历史。记录作者、审核者、独立运行标识、所收材料、实际检查、未核事项、问题和处理条件。

结论只用三种：**建议采用、需修改、证据不足**。阻断问题须解决、收窄范围或撤回相应主张后复核；非阻断建议可以说明理由后不采用。声明“暂无问题”必须对应实际检查，不能预填。审核者不另行批准任务范围；协调者核对既有授权后自动推进，超范围才交负责人。

## 版本绑定

- 被审基线和成果都写完整提交 SHA；注明覆盖的文件与检查范围。
- 审核记录在成果提交之后写入，不要求记录引用包含自身的提交 SHA。
- 写入记录后，合并者检查从被审成果到当前 HEAD 的全部差异。若仅增加本次审核记录，核实记录忠实反映审核结果；若还有正文、模板或其他文件变化，必须重新审核对应内容并绑定新 SHA。
- 基线推进或冲突解决影响研究内容时，同样复核；一次建议采用只适用于它明确覆盖的版本和范围。

合并子智能体核对固定版本、审核后唯一记录、授权范围和精确 head 检查；不重新裁决研究结论。冲突、内容变化、检查失败或审核未解决时退回，不自行修内容或绕过门禁。合并时读取实际保护和最终差异，不能沿用历史“无保护”状态。旧控制器的自动检查不证明当前新分工已经自动接线。
